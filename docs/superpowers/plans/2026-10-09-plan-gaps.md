### Task 2: Recurring scheduled actions

Ruling: no rrule dependency. Support recurring schedules with a cron expression via `Cron\CronExpression` (`dragonmantank/cron-expression`, already a Laravel dependency).

- Config shape: `config.schedule.cron` (string, cron expression) besides existing `config.schedule.at` (one-off). Optional `config.schedule.timezone` (default app tz).
- `ProcessScheduledActions`: for a cron schedule, the action is due when its next run time (computed from the last run time, or from the action's `created_at` if never run) is ≤ now. Running starts the in-app action as today; afterwards the next occurrence is generated: store `config.schedule.last_run_at` (ISO) — or use an existing column if one fits — so the same tick never runs twice and missed windows run once, not N times. A recurring action must be able to run again after it completed (read how the one-off path marks done; reopen/reset as `StartAction`/domain rules allow — status changes only via Domain actions with `forceFill`).
- Invalid cron → logged skip like the existing `Log::info('Scheduled action skipped' …)` path, no crash.
- Update the catalog importer/validation if it validates `config.schedule` (grep `schedule` in `app/Domain/Catalog`).
- Tests in `tests/Feature/Task/ProcessScheduledActionsTest.php` using `$this->travelTo()`: runs at first occurrence; not again in same window; runs again next occurrence; missed several occurrences → one run; invalid cron skipped.
- Update `docs/DATA_MODEL.md` catalog_actions config note: "schedule (`at` one-off or `cron` recurring)".
